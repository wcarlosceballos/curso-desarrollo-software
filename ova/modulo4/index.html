⚡ M4 · JavaScript

Este es el módulo más pesado del curso. Está bien que lo sea: es donde tu proyecto deja de ser una página bonita y se vuelve algo que hace.

Hasta M3 tu página mostraba lo que tú escribiste a mano. A partir de aquí, reacciona: el usuario hace algo, el sistema responde.

Qué sales sabiendo hacer

  • Que la página reaccione a clics, formularios y teclado.
  • Traer datos de otro lado y mostrarlos en pantalla.
  • Guardar información en el navegador para que persista.
  • Manejar errores sin que todo se rompa.

Contenido del módulo

  • Variables y funciones — ya los sabes de M2. Ahora con otra sintaxis.
  • Arreglos y objetos — la estructura más usada del lenguaje. Mapear una lista a pantalla es el 20 % del trabajo real.
  • El DOM — cómo JavaScript le habla a la página: crear, cambiar y borrar elementos.
  • Eventos — clic, envío de formulario, cambio. Cada interacción del usuario es un evento.
  • fetch y APIs — pedir datos a otro sistema y convertirlos con JSON.
  • Almacenamiento local — que los datos sobrevivan al cerrar el navegador.
  • Manejo de errores — try / catch. Un sistema que se cae cuando falta internet no es un sistema.

Lo mínimo para que el sistema se sienta real

Con esto ya tienes un producto funcional y no una maqueta:

<form id="agregar">
  <label for="producto">Producto</label>
  <input id="producto" required>
  <button type="submit">Agregar</button>
</form>
<table id="inventario"></table>

El usuario escribe, el sistema guarda, la tabla se actualiza. Eso ya es el inventario de la ferretería funcionando.

Lo que más se olvida

  • Validar antes de procesar. Un campo vacío rompe el sistema. Valida y muestra un mensaje claro.
  • No mostrar errores técnicos al usuario. "undefined is not a function" no le sirve a nadie. Muestra "No pudimos guardar. Intenta de nuevo."
  • Cargar antes de guardar. Al abrir la página, lee lo guardado y muéstralo. Si no, parece que el sistema perdió todo.

🗄️ M6 · Bases de datos y SQL

Sales de este módulo sabiendo guardar datos estructurados, relacionarlos entre sí y responder preguntas de tu cliente con consultas, no a mano.

Hasta aquí tu información vivía en variables y en el localStorage del navegador. Eso sirve para una maqueta; se cae cuando el cliente tiene 300 registros o cuando dos personas usan el sistema a la vez. Los datos de verdad van en una base de datos, y la base de datos no se llena haciendo localStorage.setItem: se llena con SQL.

La parte que más cuesta no es escribir el SELECT: es decidir qué va en la base y qué no. Un archivo PDF del comprobante de pago no es un dato: es un archivo. Meterlo todo a la base produce una tabla inútil.

Qué vas a aprender

  • Modelo relacional: los datos viven en tablas, y cada tabla es de un solo tema.
  • Clave primaria (PK): la columna que identifica cada fila de forma única. Nunca se repite.
  • Clave foránea (FK): una columna que apunta a la clave primaria de otra tabla. Eso es lo que "relaciona".
  • Las cuatro operaciones: SELECT, INSERT, UPDATE, DELETE.
  • JOIN: unir tablas para traer información que está repartida.
  • Normalización hasta 3FN: quitar la duplicación, hasta donde tenga sentido.
  • Índices: la estructura que hace que una consulta no revise toda la tabla.
SELECT c.nombre, COUNT(*) AS ordenes
FROM clientes c
JOIN ordenes o ON o.cliente_id = c.id
GROUP BY c.nombre;

SQL se lee casi como español

Por eso es el lenguaje más fácil de aprender de los que se usan en software. SELECT nombre FROM clientes WHERE ciudad = 'Lorica' se lee "selecciona el nombre de los clientes cuya ciudad es Lorica". Escribir la consulta en una sola línea, sin mayúsculas, ayuda más que cualquier truco.

Y una advertencia: el DELETE sin WHERE borra la tabla entera. Siempre, antes de ejecutar un UPDATE o un DELETE en datos de alguien más, escribe primero el SELECT equivalente y mira qué filas devuelve.

🌿 M5 · Git y GitHub

Sales de este módulo sabiendo guardar el progreso de tu proyecto, volver a una versión anterior cuando algo sale mal, y compartir tu trabajo con el mundo para que otra persona lo pueda ver y auditar.

Hasta aquí tu código vivía en una carpeta de tu computador. Si lo borrabas, se perdía. Si cambiabas algo y rompías todo, no había red. Ese es el problema que Git resuelve, y es un problema serio: todo trabajo de software que no tiene historial es frágil.

GitHub no es otra cosa: es donde se guardan los repositorios para que tu cliente los pueda abrir con un enlace. El repositorio es de Git; GitHub es el sitio donde lo publicas.

Qué vas a aprender

  • Repositorio: la carpeta completa con su historial, marcada con .git. No es una copia, es una memoria.
  • Commit: una foto del estado del proyecto con un mensaje que dice qué cambió y por qué.
  • Rama (branch): una línea de trabajo paralela. Sirve para probar algo dudoso sin romper lo que ya funciona.
  • Merge: unir el trabajo de una rama con la principal.
  • .gitignore: la lista de lo que no entra al repositorio (contraseñas, node_modules, archivos giantos).
  • Push y pull: mandar tus commits al remoto y traer los de otros.
  • Pull request: pedir que revisen tu cambio antes de mezclarlo.
  • Issue: un ticket donde queda anotado un problema, una idea o una tarea pendiente.

El día a día

git init                 # crear el repositorio en la carpeta
git add .                # preparar los cambios
git commit -m "Corrige el cálculo del total"
git push                 # mandar los commits a GitHub
ComandoQué hace en una frase
git statusMe dice qué cambié y qué falta por subir
git log --onelineLa lista de commits, cada uno con su mensaje
git switch -c nueva-ramaCreo una rama para trabajar aislado
git diffMuéstrame línea por línea qué cambié

Lo que nadie te cuenta

El mensaje del commit importa más que el comando. Escribes el mensaje para alguien que va a leer tu código en seis meses, y ese alguien sospechosamente vas a ser tú. git commit -m "cambié cosas" no le sirve a nadie.

Y el .gitignore se escribe antes del primer commit, no después. Lo que ya se subió queda en el historial para siempre, aunque lo borres del archivo.
